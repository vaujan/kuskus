- Prefers Markdown source editing to use an explicit 4-space indentation unit (spaces, not tab characters), overriding the editor/library default. Confidence: 0.9
- Benchmarks the app's Markdown editing behavior against Obsidian's conventions before deciding what "normal" is (indentation, frontmatter/Properties). Confidence: 0.8
- Wants YAML frontmatter to be the canonical source of truth for note properties: structured, editable Properties rows in Read/Live modes, literal YAML preserved in Markdown source mode, and `title`/`created` driving note identity. Confidence: 0.9
- Prefers typed, editable property rows (text, number, boolean, URL, date, lists) with type-aware controls, borderless at rest, and a subtle outline only on hover/focus/editing. Confidence: 0.8
- Prefers view options such as "Show properties" and "Readable line length" to live in the More (⋯) menu rather than as dedicated toolbar icons. Confidence: 0.8
- Prefers UI preferences (properties visibility, reading width) to be global and persistent across notes, views, and app restarts. Confidence: 0.7
- Prefers to brainstorm and answer structured decision questions (with a recommended option per choice) before large UI redesigns are implemented. Confidence: 0.85
- Endorses minimal root-cause fixes: CSS-only/dependency-free changes, no new abstractions, no rewriting of user-authored Markdown bytes, and one focused regression assertion per fix. Confidence: 0.7
- Wants design critiques and stress-testing sessions ("grilling") grounded in the actual codebase implementation and the app's vision docs before any evaluation begins, rather than critiquing ideas abstractly. Confidence: 0.7
- Prefers issues and options to be ranked by priority, with a clear "fix this one first" recommendation, so they can focus on the single highest-priority item instead of juggling everything at once. Confidence: 0.6
- Does not read their own codebase closely and relies heavily on AI for implementation; prefers technical claims to be verified against the actual source by the assistant and explained in plain, accessible language rather than dense internals jargon. Confidence: 0.9
